# Ubuntu – EJBCA CE + SignServer CE setup with Docker

## System
- OS: Ubuntu
- Container runtime: Docker
- Services:
  - EJBCA CE
  - SignServer CE

## Objective

Deploy:

- EJBCA CE as Certificate Authority
- SignServer CE as Signing Server

Using:

- Docker containers
- self-signed TLS generated by EJBCA
- exported ManagementCA certificate as trust anchor for SignServer

---

# Architecture

```text
EJBCA CE  → Certificate Authority (CA)

ManagementCA.pem → exported CA certificate / trust anchor

SignServer CE → signing service trusting EJBCA CA
```

---

# Step 1 – Install Docker

Update packages:

```bash
sudo apt update
sudo apt upgrade -y
```

Verify Docker installation:

```bash
docker --version
docker version
```

Add current user to Docker group:

```bash
sudo usermod -aG docker $USER
```

Logout and login again for group changes to apply.

Verify Docker works:

```bash
docker run hello-world
docker ps
```

---

# Step 2 – Pull EJBCA CE image

```bash
docker pull keyfactor/ejbca-ce:latest
```

Verify image:

```bash
docker images | grep ejbca
```

---

# Step 3 – Run EJBCA with self-signed TLS

Start EJBCA:

```bash
docker run -d \
--name ejbca \
-p 8080:8080 \
-p 8443:8443 \
-h localhost \
-e TLS_SETUP_ENABLED="simple" \
keyfactor/ejbca-ce:latest
```

Verify container:

```bash
docker ps
```

View logs:

```bash
docker logs -f ejbca
```

Access admin UI:

```text
https://localhost:8443/ejbca/adminweb
```

---

# Step 4 – Export ManagementCA certificate

Enter container:

```bash
docker exec -it ejbca bash
```

Navigate to certificate directory:

```bash
cd /opt/keyfactor/ejbca/p12
ls
```

Expected files:

```text
ManagementCA.p12
superadmin.p12
```

Exit container:

```bash
exit
```

Copy certificate to host:

```bash
docker cp ejbca:/opt/keyfactor/ejbca/p12/ManagementCA.p12 ~/ManagementCA.p12
```

Convert PKCS12 to PEM:

```bash
openssl pkcs12 -in ~/ManagementCA.p12 -out ~/ManagementCA.pem -nokeys
```

This PEM certificate is used as the trust anchor by SignServer.

---

# Step 5 – Pull SignServer CE image

```bash
docker pull keyfactor/signserver-ce:7.3.2
```

Verify image:

```bash
docker images | grep signserver
```

---

# Step 6 – Run SignServer with EJBCA CA certificate

Start SignServer:

```bash
docker run -d \
--name signserver \
-p 8081:8080 \
-p 8444:8443 \
-v ~/ManagementCA.pem:/mnt/external/secrets/tls/cas/ManagementCA.crt \
-h localhost \
keyfactor/signserver-ce:7.3.2
```

Verify:

```bash
docker ps
```

Check logs:

```bash
docker logs -f signserver
```

---

# Step 7 – Access SignServer Admin UI

Open:

```text
https://localhost:8444/signserver/adminweb
```

---

# Step 8 – Verify SignServer trusts EJBCA

Check SignServer logs:

```bash
docker logs signserver | tail -50
```

Expected:

- SignServer starts successfully
- connection to EJBCA succeeds
- no TLS trust validation errors

# Common issue avoided

## Avoid using interactive temporary containers

Incorrect:

```bash
docker run -it --rm
```

Why:

Container exits immediately when shell exits.

---

Correct:

```bash
docker run -d --name <container-name>
```

Why:

Runs container detached and keeps service alive.

# Final minimal workflow

```bash
# Verify Docker
docker run hello-world

# Run EJBCA
docker run -d --name ejbca -p 8080:8080 -p 8443:8443 -h localhost -e TLS_SETUP_ENABLED="simple" keyfactor/ejbca-ce:latest

# Export ManagementCA certificate
docker cp ejbca:/opt/keyfactor/ejbca/p12/ManagementCA.p12 ~/ManagementCA.p12

openssl pkcs12 -in ~/ManagementCA.p12 -out ~/ManagementCA.pem -nokeys

# Run SignServer
docker run -d --name signserver -p 8081:8080 -p 8444:8443 -v ~/ManagementCA.pem:/mnt/external/secrets/tls/cas/ManagementCA.crt -h localhost keyfactor/signserver-ce:7.3.2
```

# What I learned

- `TLS_SETUP_ENABLED="simple"` provides the simplest self-signed TLS setup for EJBCA CE.
- `ManagementCA.p12` can be exported and converted to PEM for external trust configuration.
- SignServer CE can trust EJBCA by mounting the exported `ManagementCA.pem` certificate into the container.
- Running containers with `-d --name` is preferred for long-running services.
- Checking container logs with `docker logs -f` is essential during first deployment verification.
